# 2026-10-20 Warm-up

## 上次 Drill 答案（2026-10-19）
題目：`@Transactional` 方法入面直接 `kafkaTemplate.send()`，有時下游查唔到訂單、有時訂單 rollback 咗消息已經發出。
- **原因**：Kafka 唔參與 DB 事務。`send()` 喺 commit **之前**已經發出——下游消費得快，DB 仲未 commit（或者下游讀從庫有延遲）→ 查唔到；之後 DB rollback，消息已經收唔返 → 錯發。
- **輕量改法**：`@TransactionalEventListener(phase = AFTER_COMMIT)`（或 `TransactionSynchronization.afterCommit`）commit 後先發。解決錯發同查唔到，但 commit 後進程掛／發送失敗會丟，要補償掃描。
- **穩陣改法**：Transactional Outbox——同一個 DB 事務寫訂單 + outbox 表，commit 後由 relay 或 CDC（Debezium）發 Kafka；至少一次投遞 + 下游用 eventId 冪等去重。
- 加分：下游查唔到亦可能係讀從庫延遲 → 消息帶齊數據或關鍵讀走主庫。
