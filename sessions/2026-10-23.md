# 2026-10-23 Java warm-up

## 上次 drill 答案（2026-10-22）

題：重放歷史數據後，實時 consumer lag 同 producer 延遲一齊飆升，點解？

- **根因：page cache 污染**。實時 consumer 平時讀尾部熱數據命中 page cache（sendfile 零拷貝）；重放 consumer 讀舊 segment，唔喺 cache → 大量磁碟隨機／順序讀，仲會把熱尾部數據擠出 page cache → 實時 consumer 都變讀盤，lag 升。
- **producer 慢**：磁碟 IO 被讀爭搶，dirty page 回寫變慢；而且 sendfile 讀未緩存數據時會阻塞 broker network／IO 線程，同一 broker 嘅 produce 請求排隊（**request queue time** 升）。
- **處理**：對重放 consumer 設 quota（`consumer_byte_rate`）限速；離峰重放；重放走獨立集群（MirrorMaker 複製）或 tiered storage；加內存、讀寫盤分離；監控 cachestat／磁碟讀 IOPS、`RequestQueueTimeMs`、`NetworkProcessorAvgIdlePercent`。
