# 2026-10-25 Java warm-up

## 上次 drill 答案（2026-10-24）

題：線上 MySQL 每隔一陣 TPS 跌到接近 0 幾秒再恢復。點樣用指標判斷係唔係 redo log 寫滿觸發同步刷髒？確認後點改？

- **核心指標 checkpoint age**：`SHOW ENGINE INNODB STATUS` 嘅 LOG 段，`Log sequence number − Last checkpoint at` = 未刷盤嘅 redo 量。對比 redo 總容量（8.0.30+ `innodb_redo_log_capacity`，舊版 `innodb_log_file_size × innodb_log_files_in_group`）。age 去到接近容量上限（大約 75% 開始激進刷、約 90% 進入同步刷髒，用戶寫線程被迫等）→ TPS 斷崖。
- **佐證**：`information_schema.INNODB_METRICS` 開 `log_lsn_checkpoint_age` 等 log 指標畫圖；跌 TPS 嗰幾秒 `Innodb_buffer_pool_pages_dirty` 急降、磁碟寫 IOPS（`iostat`）頂滿；時間點同 checkpoint age 頂峰吻合，而且有週期性。
- **排除其他**：`Innodb_buffer_pool_wait_free` 升係「冇空閒頁」（另一種刷髒）；MDL 等待、大事務寫 binlog、鎖等待都會卡，但唔會同 checkpoint age 對得上。
- **改**：加大 redo 容量（8.0.30+ 可以線上改 `innodb_redo_log_capacity`）；`innodb_io_capacity` / `innodb_io_capacity_max` 調到磁碟真實 IOPS，令後台平時刷夠；SSD 上 `innodb_flush_neighbors=0`；保持 `innodb_adaptive_flushing=ON`；批量寫分批、削峰；必要時換更快嘅盤。
