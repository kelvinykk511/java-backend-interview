# 2026-10-21 Warm-up

## 上次 Drill 答案（2026-10-20）
題目：Spring Boot 3 開咗 `spring.threads.virtual.enabled=true`，壓測 QPS 冇升反而大量超時；thread dump 見好多線程卡喺 HikariCP `getConnection()`。
- **原因**：瓶頸由「線程數」搬咗去「DB 連接數」。以前 Tomcat 200 條線程等於天然限流；虛擬線程冇上限，幾千個請求同時搶得 10～20 條連接，全部排隊等 `connectionTimeout`（預設 30s）→ 超時。虛擬線程提升吞吐嘅前提係下游頂得住。
- **加劇因素**：持連接時間長（事務入面做遠程調用/慢 SQL）；舊版 JDBC driver 內部用 `synchronized` 包 IO，JDK 21 會 pinning 佔住 carrier（`-Djdk.tracePinnedThreads=full` / JFR `VirtualThreadPinned` 確認）。
- **點改**：
  1. 用 `Semaphore`／bulkhead 喺入口限住打 DB 嘅並發（約等於連接池大小），超出就快速失敗或排隊有上限。
  2. 連接池按 **DB 承受能力** 定大小，唔好跟線程數無限加；`connectionTimeout` 調短做 fail-fast。
  3. 縮短持連接時間：事務內唔做 RPC/HTTP，優化慢 SQL。
  4. 升級 JDBC driver（較新版 MySQL Connector/J 已將 synchronized 換成 ReentrantLock）或升 JDK 24（JEP 491）減少 pinning。
- 一句：虛擬線程令「等」變平，唔會令 DB 連接變多。
