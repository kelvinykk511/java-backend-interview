# 2026-11-01 Java warm-up

## 上次 drill 答案（2026-10-31）

題：一致性雜湊自建限流計數集群（3 台 × 150 vnode，每用戶每分鐘 100 次），加第 4 台之後有用戶嗰分鐘打咗接近 200 次都冇被限流。點解？點處理？

- **點解**：加節點後大約 1/4 嘅 key 搬去新節點。新節點上呢個用戶嘅計數由 0 開始，舊節點已經計咗嘅接近 100 次冇搬過去 → 同一分鐘兩邊各放 100 次。有狀態嘅數據，一致性雜湊只係「少搬」，唔係「唔使搬」。
- **點處理**：
  - 新拓撲喺**下一個整分鐘**先生效，舊窗口由舊節點計完。
  - 或者遷移期**雙讀**：當前窗口新舊 owner 嘅計數加埋判斷。
  - 或者用 Redis Cluster（slot 遷移有 ASK 重定向），或者接受短暫誤差 + 下游二次保護。

詳見 [一致性雜湊](../distributed/consistent-hashing.md) 補充段。
