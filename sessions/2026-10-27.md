# 2026-10-27 Java warm-up

## 上次 drill 答案（2026-10-26）

題：Redis 開咗 `io-threads 4`，延遲仍然間歇飆高，`SLOWLOG` 見到對 50 萬 field 嘅 Hash 做 `HGETALL`。點解多線程 IO 救唔到？兩個改法。

- **點解救唔到**：io-threads 只係將「讀寫 socket + 解析協議」分出去；**命令執行仍然喺主線程單線程**。`HGETALL` 50 萬 field 係 O(n)，主線程要逐個遍歷再砌一個巨大回覆，期間所有其他命令都要等。回覆太大仲會脹 client output buffer。
- **改法 1：唔好一次過攞晒** → 用 `HSCAN key cursor COUNT 500` 分批，或者只攞需要嘅 field 用 `HMGET`。
- **改法 2：拆大 key** → 按 `hash(field) % N` 拆成 N 個細 Hash（例如 `user:tags:{id}:0..63`），每個幾千 field 以內。
- 加分：刪大 key 用 `UNLINK`；熱讀可加本地緩存；用 `--bigkeys` / `MEMORY USAGE` 定期掃大 key。
