# 2026-10-24 Java warm-up

## 上次 drill 答案（2026-10-23）

題：Redis 開 AOF `appendfsync everysec`，磁碟 IO 突然卡住幾秒：寫延遲點變？最壞丟幾多？點確認？

- **延遲**：主線程每輪 event loop 把 AOF buffer `write()` 落 page cache，後台 bio 線程每秒 `fsync`。如果上一次 fsync 仲未完成，主線程會**延後 write 最多 2 秒**；超過 2 秒就唔等，強行 `write()` → 磁碟卡住時 write 本身都會阻塞主線程 → **所有命令一齊卡**，P99 飆升，唔只係寫命令。
- **最壞丟數據**：約 **2 秒**（唔係 1 秒）——延後未寫嘅 buffer + 已 write 未 fsync 嘅數據。
- **確認**：日誌 `Asynchronous AOF fsync is taking too long (disk is busy?)`；`INFO persistence` 睇 `aof_delayed_fsync` 計數、`aof_pending_bio_fsync`；`LATENCY LATEST` 睇 `aof-write-pending-fsync` / `aof-write` 事件；系統層 `iostat` await/util。
- **緩解**：AOF 放獨立/更快嘅盤；避開 rewrite 同 BGSAVE 同時跑；`no-appendfsync-on-rewrite yes`（rewrite 期間唔 fsync，換更多可能丟失）。
