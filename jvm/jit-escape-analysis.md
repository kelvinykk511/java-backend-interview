# JIT 與逃逸分析

## 面試問題

JVM 的 JIT 編譯大概做什麼？逃逸分析（escape analysis）能帶來哪些優化？

## 答法

- **解釋執行 vs JIT**：熱點方法被反覆執行後，JIT 把它編成機器碼，後續直接跑原生碼，比純解釋快很多。
- **熱點偵測**：方法計數 / 回邊計數；達到閾值觸發編譯（C1 偏快、C2 偏猛，視 JVM 版本與分層編譯）。
- **逃逸分析**：分析對象會不會「逃出」方法或執行緒。
  - **不逃逸**：可做 **棧上分配**（或不真分配到堆）、**標量替換**（把對象拆成局部變數）、鎖消除。
  - **執行緒逃逸但不方法逃逸**：仍可能做部分優化。
- **面試一句話**：JIT 把熱點變快；逃逸分析讓「看起來 new 了」的對象有時根本沒進堆、鎖也可能被消掉。

## 常見追問 / 陷阱

「看到 `new` 就一定有堆分配？關掉逃逸分析效能一定變差？」

→ 不逃逸時可能沒有真實堆分配；優化依賴分析結果與編譯閾值，別把「源碼有 new」等同「一定 GC 壓力」。生產上少手動關 EA，除非在做對照實驗。
