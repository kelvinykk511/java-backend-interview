# ZGC vs G1

## 面試問題

線上服務對尾延遲很敏感，G1 跟 ZGC 你怎麼選？各自適合什麼場景？

## 答法

- **G1**：Region + 可設停頓目標（`MaxGCPauseMillis`）；多數業務預設就夠用；吞吐與停頓折衷較平衡。JDK 8u／11 常見預設。
- **ZGC**：目標是**極低且可擴展的停頓**（通常毫秒級、幾乎不隨堆變大而線性變長）；靠著色指針（colored pointers）＋讀屏障做並發標記／搬移，應用線程幾乎不被長 STW 卡住。
- **代價**：ZGC 通常多吃一點 CPU／記憶體開銷；極小堆或「只要吞吐、不怕幾十 ms 停頓」時 G1 往往更省事。
- **選法一句話**：堆大、P99／P999 敏感 → 優先評估 ZGC；常規中等堆、團隊熟 G1 日誌 → 繼續 G1 並盯 Humongous／Full GC。
- **面試加分**：兩者都仍有短 safepoint；「零停頓」是行銷說法，實務講「停頓極短且與堆大小解耦」。

## 常見追問／陷阱

「開了 ZGC 就一定比 G1 快？」

→ 不一定。ZGC 勝在**尾延遲穩定**，平均吞吐未必更高。還要看 JDK 版本（ZGC 在較新 JDK 才成熟／預設可用）、分配速率、以及是否真的被 GC 停頓打到 P99。先用 GC 日誌／APM 證明瓶頸再換。

## 小練習

服務堆 32GB，P99 偶發 200ms+，GC 日誌顯示 G1 Mixed GC 偶發偏長。你會先調 G1 還是直接切 ZGC？依據是什麼？

## 深入（2026-11-14）：分代 ZGC、allocation stall，同「零停頓」唔好混

### 面試可以點追

線上交易／行情服務對 P99 好敏感，G1 同 ZGC 點揀？開咗 ZGC 係咪一定更快？JDK 21 只加 `-XX:+UseZGC` 夠唔夠？

### 答法

**點揀（一句話仍然成立）**

- **G1**：Region + 可設停頓目標（預設 `MaxGCPauseMillis=200`）；Young／Mixed 有 STW 回收，吞吐同停頓摺中。中等堆、團隊熟 G1 日誌、可接受幾十 ms 停頓 → 繼續 G1，先盯 Humongous、Mixed 過長、evac failure／to-space exhausted。
- **ZGC**：目標係**極短、而且幾乎唔隨堆變大而線性拉長**嘅停頓（通常亞毫秒到幾毫秒）。著色指針 + 讀屏障，標記同搬移幾乎並發。大堆、P99／P999 敏感（撮合、行情、行情網關）→ 優先評估 ZGC。
- **代價**：讀屏障同並發回收通常多吃一點 CPU／內存。細堆或「只要吞吐」時，G1 往往更省事。

**2026 面試要補：分代 ZGC**

- JDK 21：`-XX:+UseZGC -XX:+ZGenerational`（要顯式打開分代）。
- JDK 23+：開 `UseZGC` **預設已經係分代**；用 `-XX:-ZGenerational` 先會退回非分代。
- 非分代 ZGC 對大量短命對象較不利，並發回收容易追唔上分配，高峰出現 **allocation stall**（應用線程卡住等回收騰出空間）。呢個唔係「又一次長 STW Mixed GC」，但用戶體感一樣係請求變慢、線程打滿。
- 切 ZGC 時順手確認 JDK 版本同有冇開分代，唔好只貼一個 `UseZGC`。

**仍然唔係零停頓**

兩者都仲有短 safepoint（例如標記週期開始／結束）。行銷講「零停頓」，面試應講「停頓極短，而且同堆大小解耦」。

### 追問／陷阱

- 「開咗 ZGC 就一定比 G1 快？」→ 否。ZGC 勝在**尾延遲穩定**，平均吞吐／CPU 未必更好。未用 GC 日誌／APM 證明 P99 係 GC 停頓打出嚟，唔好先切收集器。
- 切走之後 CPU 升高幾個月都可能係讀屏障同並發回收的正常代價；若高峰 stall、堆長期貼近 `-Xmx`，先查：有冇開分代、堆係咪太小、分配速率同大對象（一次讀晒大檔、巨型數組），而唔係斷言「ZGC 壞咗」。
- Stall 同 G1 的 evac failure／Full GC 都係「回收追唔上」，但機制唔同：G1 往往係一次較長 STW；ZGC stall 係分配路徑上等待並發回收。處理思路都係降分配、加大堆／讓回收跟上，而唔係再調一個 G1 式嘅停頓目標就了事。
