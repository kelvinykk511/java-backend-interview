# 索引：B+ 樹與最左前綴

## 面試問題

InnoDB 二級索引為什麼常用 B+ 樹？聯合索引 `(a, b, c)` 查 `WHERE b = ?` 能高效用到索引嗎？

## 答法

- **B+ 樹**：葉子串成有序鏈表，範圍掃描友好；非葉子只存鍵，扇出大、樹矮，磁盤 IO 少。
- InnoDB：**聚簇索引**（通常主鍵）葉子存整行；**二級索引**葉子存「索引列 + 主鍵」，回表再拿完整行。
- **最左前綴**：聯合索引必須從最左列開始連續匹配。`(a,b,c)` 可高效用：`a`、`a+b`、`a+b+c`；單用 `b` 或 `c` 一般**用不上**（或最多 index skip scan，別當默認答案）。
- 覆蓋索引：查詢列都在索引裡 → 可不回表。

## 常見追問 / 陷阱

「`WHERE a = 1 AND c = 3` 呢？」

→ 能用到 `a` 這一段；`c` 通常無法形成連續範圍，優化器可能只用 `a` 再過濾 `c`。
