# 事務隔離級別

## 面試問題

MySQL（InnoDB）有哪些事務隔離級別？分別解決什麼問題？

## 答法

從低到高（隔離越強，併發通常越差）：

1. **READ UNCOMMITTED**：能讀到別人未提交的改動（髒讀）。實務幾乎不用。
2. **READ COMMITTED**：只讀已提交；避免髒讀，仍可能不可重複讀。
3. **REPEATABLE READ**（InnoDB **默認**）：同一事務內多次讀同一行，結果一致；靠 MVCC + 間隙鎖等減少幻讀。
4. **SERIALIZABLE**：最嚴，讀也加鎖，併發最差。

髒讀 / 不可重複讀 / 幻讀：

- **髒讀**：讀到未提交數據
- **不可重複讀**：同行兩次讀到不同值（被別人改了）
- **幻讀**：範圍查詢兩次行數不一樣（被別人插入/刪除）

## 常見追問 / 陷阱

「RR 一定沒有幻讀？」

→ 標準 SQL 裡 RR 不保證消滅幻讀；InnoDB 用 Next-Key Lock 等在很多場景能避免，但別絕對說「RR = 零幻讀」。

## 小練習

默認是 RR。什麼業務場景你會刻意改成 READ COMMITTED？心裡想一個例子。
