# 事務傳播實戰：REQUIRED / REQUIRES_NEW / NESTED

## 面試問題

Spring 事務傳播裡，`REQUIRED`、`REQUIRES_NEW`、`NESTED` 差別是什麼？各舉一個適合用的場景。

## 答法

（前提：經 Spring 代理調用才生效；同類 `this.xxx()` 自調用不算。）

| 傳播 | 行為（白話） | 適合場景 |
|------|--------------|----------|
| **REQUIRED**（默認） | 有就加入，沒有就新建；同一事務一起提交/回滾 | 大多數業務寫入 |
| **REQUIRES_NEW** | 掛起外層，**獨立新事務**；內層先提交，外層之後回滾也回不掉內層 | 審計日誌、發送記錄「一定要留下」、與主單成敗解耦 |
| **NESTED** | 外層有事務時開 **存檔點（savepoint）**；內層回滾只回到存檔點，外層還可繼續 | 批次裡「某一筆失敗可跳過，整批還要提交」 |

對比口條：

- `REQUIRES_NEW`：真的兩筆 DB 事務，內層已提交對外層不可見回滾。
- `NESTED`：還在同一外層事務裡，靠 savepoint；外層最終回滾則內層改動也沒了。
- 別和「新線程 / `@Async`」搞混：異步方法預設不在原事務裡，要另開事務得自己標。

## 常見追問 / 陷阱

「下單失敗要回滾訂單，但『嘗試次數』日誌一定要留下——用哪個？」

→ 日誌方法用 **`REQUIRES_NEW`**（或乾脆非事務寫入獨立數據源）。若用默認 `REQUIRED`，主單回滾會把日誌一併回滾。
