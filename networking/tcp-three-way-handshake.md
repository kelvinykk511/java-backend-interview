# TCP 三次握手與 TIME_WAIT

## 面試問題

為什麼 TCP 要三次握手？服務端主動關閉連線後，為什麼常看到很多 `TIME_WAIT`？

## 答法

**三次握手（記目的，別只背步驟）**

1. Client → SYN  
2. Server → SYN + ACK  
3. Client → ACK  

目的：雙方確認「我能發、你能收」，並同步初始序號（ISN）。兩次不夠：無法確認「回程」也通，且容易被舊的重複 SYN 搞出半開連線。

**四次揮手（對照一句）**

全雙工，兩邊各自關發送方向，所以常見四次；其中一端 `FIN` 後進入等待，確保對方的 ACK 與殘留封包處理完。

**TIME_WAIT**

- 主動關閉的一方關完後會待約 2MSL。
- 兩個理由：讓最後的 ACK 有機會重傳；讓舊連線的遲到封包在網路上消失，避免污染新連線（同四元組）。
- 短連線很高的服務（大量短 HTTP）會堆積 `TIME_WAIT` → 優化方向多是連線複用（keepalive / 連線池），不是亂調內核參數當第一招。

## 常見追問 / 陷阱

「三次握手第三次丟了會怎樣？」

→ Server 已認為連上，Client 可能重發 ACK；若 Client 放棄，Server 上會留一個待超時的半連線。實務靠超時回收。
