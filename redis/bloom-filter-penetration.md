# 布隆過濾器與緩存穿透

## 面試問題

緩存穿透是什麼？布隆過濾器（Bloom Filter）怎麼擋？它有什麼代價？

## 答法

- **穿透**：查「根本不存在」的 key（惡意亂 ID、掃庫）。Cache miss → 每次打 DB；空結果若不緩存，DB 被打穿。
- **第一道：空值短 TTL**：查無則寫 `null`／空標記，TTL 很短（幾十秒～幾分鐘），擋住重複打穿。簡單，但惡意海量不同 key 仍會灌爆緩存。
- **布隆過濾器**：一組 bit 陣列 + 多個 hash。插入時把對應 bit 置 1；查詢時若任一 bit 為 0 → **一定不存在**（可擋掉）；全為 1 → **可能存在**（再查緩存／DB）。
- **CEX／業務語感**：會員 ID、幣對、提現地址白名單之類「集合是否存在」預檢，先 Bloom 再打重庫。
- **代價要講得出**：
  - **誤判（false positive）**：說「可能有」但其實沒有 → 多一次 DB／緩存查，可接受。
  - **不能刪（標準 Bloom）**：bit 共享，刪一個會影響其他；要刪用 Counting Bloom／定期重建。
  - **要與資料源同步**：新註冊／新上幣要 `add`；全量重建時機要想好。

一句話對比昨天的**擊穿**：擊穿是「熱點 key 剛好過期」；穿透是「key 從沒存在過」。

## 常見追問／陷阱

「Bloom 說存在就一定有？」→ 否，只有「說不存在」是準的。誤判率跟 bit 數、hash 數、元素量有關，面試能說「空間換誤判上限」即可。

「只用空值緩存夠不夠？」→ 固定無效 key 夠用；海量隨機 key 攻擊要 Bloom 或網關限流／鑒權擋在前面。

## 深入（2026-11-09）：穿透 vs 擊穿、空值、重建同 CEX 場景

### 面試問題

緩存穿透同擊穿點分？布隆過濾器點同「空值短 TTL」配合？Bloom 唔能刪、要重建時線上點平滑切？誤判（false positive）喺業務上可以接受咩？

### 答法

**穿透 vs 擊穿 vs 雪崩（一句分清）**

| 問題 | 特徵 | 典型防法 |
|------|------|----------|
| **穿透** | key **從不存在**（亂 ID、掃庫）→ 每次打 DB | Bloom 擋「一定無」；空值短 TTL；網關鑒權／限流 |
| **擊穿** | **熱點 key 剛好過期**，大量併發打穿 DB | 互斥重建／邏輯過期；見 cache-aside 筆記 |
| **雪崩** | 大量 key **同時過期**或 Redis 掛 | 過期加抖動；多級緩存；依賴降級 |

**防穿透組合（面試主線）**

1. **空值短 TTL**：DB 查無 → 緩存 `null`／空標記（几十秒～幾分鐘）。擋「同一個無效 key 反覆打」。簡單，但敵手換海量**不同**亂 key 仍會灌爆緩存同 DB。
2. **Bloom 前置**：請求先問 Bloom；任一 bit 為 0 → **一定不存在**，直接拒／返空，**唔打 DB**。全 1 → 可能存在，再走 Cache-Aside。
3. **外層**：登錄態、WAF、按 IP／uid 限流，唔好單靠應用層硬抗掃庫。

**Bloom 代價同同步（要講得出）**

- **False positive**：話「可能有」但其實無 → 多一次緩存／DB 查，通常可接受；**false negative 喺標準 Bloom 唔應該出現**（bit 只置 1 唔清 0）。
- **唔能刪**：刪一個元素會誤傷其他 bit。下架幣對／禁用地址 → 用 Counting Bloom，或**定期全量重建**。
- **同數據源同步**：新用戶／新充值地址／新上幣要 `ADD`；漏加會造成「真係有但被擋」（呢個係同步 bug，唔係誤判）。
- **重建平滑**：唔好 `DEL` 舊 key 再慢慢 `ADD`（中間窗口會誤傷老數據）。用**雙 Buffer**（新 key 建好再原子切別名／改配置），或重建期間 **fail-open**（Bloom 不可用就跳過擋板、只靠空值＋限流，並打告警）。

**CEX 語感**

- 充值／提現地址、幣對、UID 是否存在：先 Bloom 再查庫，擋住掃地址攻擊。
- 誤判「可能存在」→ 多一次查庫，OK；若業務錯誤地把「Bloom 說有」當成「一定有」而跳過校驗 → **事故**。Bloom 只係負向過濾器。

### 追問／陷阱

- 「Bloom 說存在 = 一定有」→ **錯**；只有「說不存在」可靠。
- 「穿透用互斥鎖？」→ 互斥係擊穿套路；穿透係海量唔同唔存在 key，鎖冇用，要用 Bloom／空值／限流。
- 重建時 `DEL` + 慢速回填 → 線上短暫把合法流量當不存在；面試要講雙 Buffer 或 fail-open。
- RedisBloom 模組 vs 自研 bitset：生產優先模組／中間件，注意持久化同主從複製係咪包含 Bloom 狀態。
