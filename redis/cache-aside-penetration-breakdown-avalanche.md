# Cache-Aside 與穿透 / 擊穿 / 雪崩

## 面試問題

常見緩存用法是什麼？緩存穿透、擊穿、雪崩分別是什麼、怎麼防？

## 答法

**Cache-Aside（旁路緩存，最常見）**

- 讀：先 Redis；沒有再查 DB，回寫緩存。
- 寫：先更新 DB，再刪（或更新）緩存。面試常偏向「刪緩存」，避免髒寫。

三種事故（記名字 + 一句防法）：

| 問題 | 是什麼 | 常見防法 |
|------|--------|----------|
| **穿透** | 查根本不存在的 key，每次打穿到 DB | 空值短 TTL 緩存；布隆過濾器擋掉明顯無效 key |
| **擊穿** | 熱點 key 剛好過期，瞬間大量請求打 DB | 熱點永不過期 / 邏輯過期；互斥鎖只讓一條去重建 |
| **雪崩** | 大量 key 同時過期，或 Redis 掛了 | TTL 加隨機抖動；多級緩存；Redis 高可用 |

## 常見追問 / 陷阱

「先更新緩存再寫 DB」行不行？

→ 容易不一致（寫 DB 失敗時緩存已是新值）。實務更常見：先 DB，再刪緩存；再靠 TTL 兜底。

## 小練習

穿透和擊穿差在哪一句話？「key 根本不存在」vs「熱點 key 剛好過期」。
