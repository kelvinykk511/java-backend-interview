# 一致性雜湊（Consistent Hashing）

## 面試問題

緩存節點加減時，為什麼常用一致性雜湊而不是 `hash % N`？虛擬節點在解決什麼？

## 答法

- **`hash % N`**：N 一變，幾乎所有 key 映射全變 → 緩存雪崩式失效 / 數據大遷移。
- **一致性雜湊**：把節點與 key 都映射到同一個環上；key 順時針找第一個節點。加減一台，通常只影響鄰近一小段 key。
- **虛擬節點（vnode）**：一台物理機在環上掛很多虛擬點，負載更均勻，也避免「節點太少時傾斜」。
- **面試一句話**：一致性雜湊降低「變節點數」時的震動；vnode 解決均勻與熱點。Redis Cluster 用的是槽位（16384），思路相近但實現不同——別混成同一套。

## 常見追問 / 陷阱

「一致性雜湊能保證每台負載一樣嗎？」

→ 不能保證絕對均勻；節點少或 key 分佈偏斜時仍會熱點。所以要 vnode，且熱 key 還要業務層拆分（本地緩存、打散 key）。

## 小練習

CEX 把某用戶 session / 限流計數放在自建緩存集群。加機器時你選 `hash % N` 還是一致性雜湊？要不要 vnode？一句話理由。
